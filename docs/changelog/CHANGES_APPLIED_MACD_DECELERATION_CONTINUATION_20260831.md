# CHANGES_APPLIED_MACD_DECELERATION_CONTINUATION_20260831.md

Документирует изменения, применённые по итогам «Аудит «Замедление
MACD с продолжением»» и «Промт исправление стратегии «Замедление
MACD с продолжением»» (31.08.2026), плюс сверку с «Торговая система
«Замедление MACD с продолжением»» и докстрингом самого файла
стратегии. Валидировано в этом окружении: `npm install`, `npm run
typecheck`, `npm run lint`, `npx vitest run` (647/647 тестов, включая
переписанный `strategies.test.ts` для этой стратегии — 38 тестов).

**Затронутые файлы:** `src/compute/IndicatorAggregator.ts` (2 строки),
`src/compute/patterns/macd-deceleration-continuation.ts` (полная
переработка), `src/compute/patterns/strategies.test.ts` (переписан
набор тестов для `detectMacdDecelerationContinuation`, включая
вспомогательный фикстур-билдер `macdDecelScenario`).

## 1. [Критично] RSI-инвалидатор тихо отключался конфигурацией UI

**Файл:** `src/compute/IndicatorAggregator.ts`

`needRsi = has('rsi') || has('mean-reversion')` не включал эту
стратегию — если пользователь включал ТОЛЬКО
`macd-deceleration-continuation` без `rsi`/`mean-reversion`,
`snapshot.rsi` был `null`, и хард-инвалидатор «RSI не пересёк 50»
молча пропускался. Исправлено: `needRsi` теперь также проверяет
`has('macd-deceleration-continuation')`.

## 2. [Высокая] Отсутствовал порог входа (ENTRY_THRESHOLD)

**Файл:** `macd-deceleration-continuation.ts`

Без явного порога сигналы с confidence≈0.34–0.40 (на грани случайного)
проходили наравне с «сильными». Добавлена константа
`ENTRY_THRESHOLD = 0.55` (нижняя граница рекомендованного диапазона
0.55–0.6) и финальная проверка `if (confidence < ENTRY_THRESHOLD)
return null;`.

**Важный вывод по итогам реализации** (эмпирический, не был известен
заранее): при связке текущей формулы confidence (`0.4 + до 0.15 от
отношения магнитуды флип-бара к пиковому бару коррекции`) с
остальными гейтами (decay, пауза, направление) базовая confidence для
реалистичных M1-сценариев MACD(12,26,9), которые удалось построить и
провалидировать против настоящих `macd()`/`computeStructure()`,
упирается в потолок ~0.40–0.42 — то есть НИЖЕ ENTRY_THRESHOLD без
бонуса Kill Zone и/или Order Block confluence. Это, по сути, делает
confluence фактически обязательным на практике, хотя «Торговая
система», §8 явно описывает оба бонуса как опциональные. Требует
проверки на реальном бэктесте (см. п.6 ниже и «жёсткие ограничения»
исходного промта — полный бэктест-прогон явно вынесен за рамки этого
точечного промта).

## 3. [Средняя] Пауза-свеча технически совпадала со свечой флипа

**Файл:** `macd-deceleration-continuation.ts`

`pauseIdx = candles.length - 2` совпадал с абсолютным индексом
`flipIdx` — «пауза» и «флип» были гарантированно одной и той же
свечой. Первоисточник методички недоступен, поэтому трактовка выбрана
по явной инструкции промта-фикса: пауза — последний бар старой серии,
на один бар раньше `flipIdx`; пересчёт в абсолютный индекс свечи идёт
через `windowStart` (а не через `candles.length - N` напрямую) —
именно смешение этих двух систем координат было причиной исходного
смещения. Задокументировано в коде как явная развилка трактовки.

## 4. [Средняя] Отсутствовало подтверждение силы тренда по ADX

**Файлы:** `macd-deceleration-continuation.ts`,
`IndicatorAggregator.ts`

15-барное структурное окно (`computeStructure`) само по себе шумное
на форекс M1. Добавлен `ADX_TREND_CONFIRM = 20` и гейт
`if (snapshot?.adx != null && snapshot.adx < ADX_TREND_CONFIRM) return
null;`. По тому же принципу, что и в п.1, `needAdx` в
`IndicatorAggregator.ts` обновлён: `has('atr') || has('macd-deceleration-continuation')`
— иначе новый гейт воспроизвёл бы тот же класс бага (тихое отключение
конфигурацией UI).

## 5. [Низкая] Проверка затухания серии была слишком строгой/шумочувствительной

**Файл:** `macd-deceleration-continuation.ts`

Строгое `<=` между соседними барами гистограммы засчитывало шумовые
колебания (типичные на M1 из-за малых абсолютных значений гистограммы)
как «уверенное затухание». Заменено на относительный шаг:
`DECAY_STEP_RATIO = 0.9` — каждый следующий бар должен быть не больше
90% предыдущего. Начальное консервативное значение, отмечено как
кандидат на уточнение бэктестом.

## 6. [Низкая] Параметры MACD были жёстко зашиты (12/26/9)

**Файл:** `macd-deceleration-continuation.ts`

Добавлен необязательный 4-й параметр
`macdConfig?: { fast: number; slow: number; signal: number }` с
дефолтом 12/26/9 (обратная совместимость). **Сознательно не
прокинуто** через `index.ts`/`full-snapshot.ts` — это потребовало бы
трогать общие файлы за пределами разрешённого списка («жёсткие
ограничения» промта: только `IndicatorAggregator.ts` и сам файл
стратегии). Рекомендация: отдельным точечным промтом прокинуть
`config.macdFast/macdSlow/macdSignal` из `IndicatorConfig`.

## 7. [Доп., сверх аудита] Флип-бар мог не совпадать по направлению с трендом

**Файл:** `macd-deceleration-continuation.ts`

Направление сделки бралось только из `computeStructure`, без проверки,
что сама гистограмма флипнула В СТОРОНУ тренда — теоретически
возможен был `buy`-сигнал на флипе гистограммы в минус. Добавлена
явная проверка совпадения знака.

## 8. [Доп., сверх аудита] Многобарная проверка глубины коррекции по Фибо

**Файл:** `macd-deceleration-continuation.ts`

«Торговая система», §7 требует проверку 78.6%-инвалидации на КАЖДОМ
баре коррекции, а не только на последней свече. Раньше проверялся
только последний бар. Теперь — весь диапазон коррекционной серии.

## 9. [Реализовано 31.08.2026, доп. запрос] Хард-гейт `|lastValue| < |flipValue|`

**Файлы:** `macd-deceleration-continuation.ts`

Изначально сознательно не добавлялся: докстринг стратегии буквально
описывает «первый бар нового цвета меньше по модулю последнего бара
старого цвета», но арифметика показывала, что в связке со СТАРОЙ
формулой confidence (`0.4 + до 0.15 от |lastValue|/|oldSeries[0]|`)
такой гейт ограничивает confidence сверху величиной ~0.51 — жёстко
ниже `ENTRY_THRESHOLD=0.55` без бонуса, что противоречит «Торговая
система», §8 («бонус, а не обязательный гейт»).

По прямому запросу это доработано: гейт добавлен, и ОДНОВРЕМЕННО (как
и было явно запланировано в исходном комментарии-развилке)
перекалибрована сама формула confidence — см. п.11 ниже.

## 10. [Реализовано 31.08.2026, доп. запрос] Фильтр «флип-бар шире 2×ATR — новостной выброс»

**Файлы:** `macd-deceleration-continuation.ts`, `IndicatorAggregator.ts`

«Торговая система», §7. Требовал `snapshot.atr`, которое вычислялось
только при `needAtr = has('atr')` — правка этого флага изначально
не входила в разрешённый список правок `IndicatorAggregator.ts`
(только `needRsi`/`needAdx`). По прямому запросу область правок
`IndicatorAggregator.ts` расширена: `needAtr` теперь тоже включает
`has('macd-deceleration-continuation')`, по тому же принципу, что и
`needRsi`/`needAdx` (иначе новый гейт воспроизвёл бы тот же класс
бага — тихое отключение конфигурацией UI). Сама проверка:
`if (flipBody > snapshot.atr * 2) return null;`, где `flipBody` —
тело флип-бара (последней свечи).

## 11. [Реализовано 31.08.2026, доп. запрос] Перекалибровка формулы confidence

**Файл:** `macd-deceleration-continuation.ts`

Необходимое следствие п.9: старая формула измеряла «силу флипа»
(`|lastValue|/|oldSeries[0]|`), что структурно конфликтовало с новым
гейтом (который требует, чтобы `|lastValue|` было МЕНЬШЕ, а не
больше). Новая формула измеряет качество самого сетапа вместо силы
флипа:

- `decayQuality` — длина подтверждённой decay-серии сверх минимума
  (`MIN_SERIES_LENGTH=4`), выходит на максимум при 10+ барах серии;
- `quietness` — насколько `lastValue` меньше `flipValue` в
  относительных величинах (буквально определение паттерна из
  докстринга);
- `confidence = 0.4 + decayQuality×0.12 + quietness×0.12` (диапазон
  до бонусов: 0.4–0.64, был 0.4–0.55).

Коэффициенты (0.12, кап decay в 6 доп. баров) выбраны по аналогии со
старым коэффициентом 0.15 и, как и остальные пороги в этом файле,
являются кандидатами на уточнение бэктестом. Провалидировано на
известной ранее фикстуре (та же, что использовалась для находки в
исходном промте): confidence вырос с ~0.404 до ~0.560 — теперь
СВЕРХ `ENTRY_THRESHOLD` без единого бонуса, как и требует «Торговая
система», §8.

## Дополнение (перенос из параллельной сессии правок этой же стратегии)

По итогам сравнительного аудита этой ветки против параллельной версии
(`80-main-macd-deceleration-fixed`, только пункты 1–6) перенесены три
элемента, которые в этой ветке отсутствовали или были утрачены:

1. **Проброс `config.macdFast/macdSlow/macdSignal` из настроек UI.**
   `patterns/index.ts`: `detectAllPatterns(...)` снова принимает
   опциональный `macdConfig` и передаёт его в
   `detectMacdDecelerationContinuation(...)`. `full-snapshot.ts`: вызов
   `detectAllPatterns(...)` снова собирает `macdConfig` из `config.*`.
   Без этого стратегия была навсегда заперта на дефолтных MACD(12,26,9)
   независимо от настроек пользователя — реальный регресс относительно
   параллельной ветки, а не просто "не сделано в рамках промта".
2. **Тест на индексацию паузы** (`treats the bar before flipValue's
   candle as the pause candle, not the flip/trigger bar itself`,
   `strategies.test.ts`) — прямая, изолированная проверка `pauseAbsIdx`
   (п.3), адаптированная под `macdDecelHappyPath()` этой ветки. При
   портировании выяснилось, что на этой фикстуре 10-барное среднее тело
   свечи вокруг паузы (~0.0008) намного меньше, чем в исходном тесте —
   дельта тела в "маленьком" сценарии подобрана заново под эту фикстуру,
   и `high`/`low` целевой свечи намеренно не трогаются (эта свеча попадает
   в 15-барное окно `computeStructure`, и их изменение искажало
   `swingHigh`/ретрейсмент — постороннее вмешательство, не относящееся к
   проверке тела паузы).
3. **Wiring-тесты `needRsi`/`needAdx`** (`indicators.test.ts`,
   `describe('computeIndicators (needRsi/needAdx feature wiring)')`) —
   прямая проверка на уровне `IndicatorAggregator`, а не только косвенно
   через поведение детектора. Дополнительно добавлен третий тест на
   `needAtr` (которого не было в исходнике переноса, т.к. в параллельной
   ветке фильтра по ATR не было вовсе) — по тому же принципу, раз
   `needAtr` в этой ветке тоже завязан на эту стратегию (п.10).

Комментарий в `macd-deceleration-continuation.ts` про "сознательно не
прокинуто через index.ts/full-snapshot.ts" (п.6) обновлён — он больше не
соответствует действительности.

Проверено заново после переноса: `tsc --noEmit` — 0 ошибок; `eslint` на
всех затронутых файлах — чисто; `vitest run` (весь проект) —
**653/653** (было 649; +4: тест паузы, `needRsi`, `needAdx`, `needAtr`).
