# Фикс: R-модель бэктеста согласована с реальной экономикой демо-счёта — 2026-09-13

## Проблема

`backtest/metrics.ts` считал исход сделки в R-мультипликаторах:

```ts
const WIN_R = 2;   // выигрыш -> +200% от риска
const LOSS_R = -1; // проигрыш -> -100% от риска
```

Это классическая модель со стоп-лоссом/тейк-профитом 2:1 (риск $1 → цель
$2). Реальный демо-счёт (`useDemoAccountStore.ts`) и калибровка
(`pattern-reliability-calibration.ts`) считают исход как **бинарный
контракт**: выигрыш даёт `+profitPercent%` от ставки (по умолчанию 80%),
проигрыш забирает **всю** ставку. Это две разные экономики с разной точкой
безубыточности:

| Модель | Выигрыш даёт | Безубыток |
|---|---|---|
| Бэктест (старая, R-модель) | +200% | 33.3% |
| Демо-счёт (реальная) | +80% | 55.56% |

`averageR`/`profitFactor`/`maxDrawdownR` в обычном отчёте `npm run
backtest` не переводились напрямую в то, что реально произойдёт на демо-
счёте — бэктест считал систему прибыльной при винрейте, при котором демо-
счёт продолжал бы терять деньги. Это ограничение было зафиксировано (но
не устранено) в `docs/audit/WALK_FORWARD_PROTOCOL.md` при внедрении
форвард-тест протокола (см. `CHANGES_APPLIED_WALK_FORWARD_PROTOCOL_20260913.md`).

## Фикс

`backtest/metrics.ts::computeMetrics(trades, profitPercent)` — `profitPercent`
теперь обязательный параметр (без тихого дефолта, по аналогии с
`suggestedMultiplierFromWinRate` из более раннего фикса):

- `win` → `+profitPercent/100` (доля от ставки, а не фиксированные +200%);
- `loss` → `-1` (вся ставка, как и раньше — здесь модели совпадали);
- `timeout` → `0` (ставка возвращается).

`computeSplitMetrics`, `computeMetricsBySession` — тот же параметр
проброшен дальше. Все вызывающие места обновлены:
`backtest/change-registry.ts` (переиспользует `profitPercent`, уже
принимаемый `computeForwardTestReport`, — теперь он управляет и точкой
безубыточности вердикта, и самой доходностью в метриках, а не два
независимых допущения об экономике), `backtest/index.ts` (новый CLI-флаг
`--profit-percent` теперь используется здесь же, не только в форвард-тест
секции), `backtest/harmonic-audit.ts` (использует
`DEFAULT_PROFIT_PERCENT_FALLBACK=80`, экспортированный из
`pattern-reliability-calibration.ts`, — не изобретает свою копию дефолта).

**Спред больше не вычитается непрерывно из R.** В контракте с
фиксированной выплатой payout не масштабируется от того, насколько сильно
цена прошла порог — весь смысл "бинарности" в том, что либо получаешь
полный payout, либо ничего. Реальная стоимость спреда уже полностью
учтена выше по пайплайну: `decision/apply-spread.ts::applySpreadToOutcome()`
переразмечает пограничные `'win'` в `'timeout'` ДО того, как сделка вообще
попадает в `computeMetrics`. Продолжать вычитать спред ещё и здесь было бы
двойным учётом одной и той же стоимости. `spreadCostR` остаётся на
`SimulatedTrade` и в таблице сделок отчёта как диагностическое поле
("Spread Cost (diag.)"), просто больше не входит в расчёт доходности.

**Попутно исправлено смежное расхождение**, обнаруженное при разборе:
`winRate` в `BacktestMetrics` считался как `wins/total`, включая timeouts
в знаменатель, — единственное место в проекте, где винрейт считался так
(`useAnalyticsStore.recomputeStats()` на реальных демо-сделках и новый
`computeForwardTestReport()` всегда делят на `wins+losses`, исключая
timeout). Из-за этого `winRate` был занижен на любой выборке с ненулевыми
timeout и искажал вердикт форвард-теста в сторону "below-breakeven"
сильнее, чем обосновано данными. Теперь везде единообразно
`wins/(wins+losses)`.

**Поля интерфейса не переименованы** (`averageR`, `maxDrawdownR`) — чтобы
не расширять правку на JSON-схему потребителей без отдельного решения — но
подписи в консольном/markdown-отчётах (`backtest/report.ts`) изменены на
"Average Return"/"Max Drawdown" с единицей `/stake` вместо вводящего в
заблуждение "R". Шапка отчёта (консоль, markdown, JSON `parameters`) теперь
явно печатает использованный payout.

Диапазоны весов/порогов/множителей не менялись.

## Тесты

`backtest/backtest.test.ts`, блок `describe('metrics')` переписан:
- `winRate` тест переименован и обновлён — 2 win / 1 loss / 1 timeout из 4
  сделок теперь даёт `2/3`, а не `0.5`;
- "average R" тест переименован в "average return", пересчитан вручную для
  payout=80% (`(0.8 + (-1)) / 2 = -0.1`);
- новый тест: более высокий payout при той же последовательности
  win/loss даёт более высокую среднюю доходность (сверено на payout=100%,
  где `(1 + (-1)) / 2 = 0`);
- `profit factor` тест пересчитан для payout=80%
  (`grossProfit=1.6, grossLoss=1 -> 1.6`, было `4` при старой R=2 модели);
- `max drawdown` тест не изменил ожидаемое значение (2.0) — в этом
  конкретном сценарии просадка достигается двумя подряд убытками ДО
  следующего выигрыша, поэтому не зависит от величины payout; явно
  прокомментировано в тесте, чтобы не выглядело забытой правкой;
- Brier score и reliability bins — не связаны с R-моделью, только добавлен
  обязательный второй аргумент.
