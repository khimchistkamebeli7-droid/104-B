Основание: разбор двух отчётов A′.5 (форекс 4 пары, крипто 4 монеты, 2026-03-01 → 2026-09-17) и кода. Правки внесены поэтапно, каждая — с тестом, который **падает на старом коде и проходит на новом** (проверено откатом).

Уже было в поставке до этой сверки (2026-09-19, не переделывалось): исправление `weakClose` (sell) в `pattern-context.ts`; пропуск объёмного гейта при `volume≡0` в `abandoned-baby-*` (`triple.ts`) и `consolidation-breakout.ts`; перегенерация `pattern-horizon-table.ts`.

## Фаза 0 — утечка нативной памяти (`src/compute/session-regime.ts`)
- **Найдено:** `localHourToUtc` создавала `new Intl.DateTimeFormat(...)` на каждый вызов; в бэктесте — сотни тысяч раз. RSS раздувался до нескольких ГБ при почти пустой JS-куче (замер: 2.5 ГБ против 170 МБ на 40 тыс. баров), раннер GitHub Actions обрывал задачу.
- **Сделано:** форматтер кэшируется по часовому поясу (`HOUR_FORMATTERS`); смещение по-прежнему считается на каждый вызов — поведение на границах DST не менялось.
- **Проверено:** результаты аудита идентичны до/после на одном и том же датасете; `session-regime.test.ts` зелёный.

## Фаза 1 — тест зеркальной симметрии (`src/compute/patterns/mirror-symmetry.test.ts`)
- Новый тест: `nextCandleConfirmation(buy)` на исходных свечах == `(sell)` на зеркальных, 20 000 случайных пар. На старой формуле `weakClose` падает.

## Фаза 2 — нулевой объём (Deriv/форекс: `volume ≡ 0`)
- **Найдено:** жёсткие гейты `avgVol > 0 ? … : 0` + `ratio < 1.0/1.3 → null` делали детекторы структурно мёртвыми.
- **Сделано:** `hasReliableVolume()` (образец — `impulse-breakout.ts`): при отсутствии объёма фильтр пропускается, `volumeConfirmed = false`, множитель нейтрален; при реальном объёме поведение и пороги прежние. Затронуты: `double.ts` (bullish/bearish-engulfing, piercing-line, dark-cloud-cover), `triple.ts` (morning-star, evening-star).
- **Тесты (`patterns.test.ts`):** по детектору — «срабатывает при volume=0» и «не срабатывает при реальном низком объёме».
- **Последствие:** число сигналов вырастет → таблицу горизонтов нужно пересчитать (см. ниже).

## Фаза 3 — `pin-bar`
- `htfAlignment` получает `htfStructure` (а не M1-структуру); близость к swing — направленная (`isNearSwingLevelForDirection` в `pattern-context.ts`: buy — только swing low, sell — только swing high). `isNearSwingLevel` не менялась (используется другими детекторами).

## Фаза 4 — аудит (`backtest/horizon-audit.ts`)
- **Дедупликация (`dedupeOccurrences`):** один экземпляр паттерна срабатывает на десятках подряд идущих баров, а горизонты перекрываются; биномиальный тест считает их независимыми. Добавлены поля `independentCount`, `independentTestDecided`, `testAccuracyDeduped`, `pValueDeduped` (**только добавлены**; `pValue`/`significant`/Holm и формат для генератора не менялись; occurrence-кэш и `OCCURRENCE_ALGORITHM_VERSION` не затронуты).
- **Паттерны без срабатываний** (`seedNoDetectionGroups`): раньше группы строились только из встреченных occurrences → такие паттерны молча исчезали, «Нет срабатываний: 0» было верно всегда.
- Отчёт: колонки «Независимых», «p (дедуп.)»; «Train+Val» в walk-forward → «Σ train по фолдам» (это сумма по фолдам); метка источника по реальному маршруту (`isDerivSupported`); пометка «значимо ХУЖЕ 50%».
- Тесты: `horizon-audit-walkforward.test.ts` (+5).

## Фаза 6 — режим «только с доказательствами»
- `requireHorizonEvidence` (по умолчанию **false** — поведение прежнее). При `true` сигнал паттерна подавляется, если в таблице горизонтов нет записи `valid`. Сигналы без паттерна не затрагиваются. Цепочка: `settingsStore` → `useTickStore` → `DecisionEngine` → `buildSignal`; переключатель — «Сигнальный движок» в `SettingsPanel`.
