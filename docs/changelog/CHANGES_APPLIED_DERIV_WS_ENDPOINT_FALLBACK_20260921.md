# CHANGES_APPLIED_DERIV_WS_ENDPOINT_FALLBACK_20260921.md — резервные WS-эндпоинты Deriv

Дата: 2026-09-21.

## Симптом

Форекс-пары показывают «нет подключения». В `ROUTING_CHAIN.forex` первым
идёт `deriv`; в сборке без Supabase-прокси (`VITE_SUPABASE_URL` не задан)
источники `yahoo`/`twelvedata`/`finnhub` заведомо падают («proxy required»), то
есть для форекса Deriv — фактически ЕДИНСТВЕННЫЙ рабочий источник.

## Причина (по коду)

1. `DerivSource` подключался к ОДНОМУ жёстко зашитому хосту
   (`wss://ws.derivws.com/...`). Недоступность этого хоста = полный отказ
   форекса, без альтернативы.
2. У попытки подключения не было таймаута: «зависший» хост держал `connect()`
   до внутренних таймаутов, а не секунды.
3. Побочный дефект: `ConnectionManager.trySource()` на каждую попытку создаёт
   новый `DerivSource` и при ошибке НЕ вызывает `disconnect()`. У провалившегося
   экземпляра оставался `activeSymbol`, и его `onclose` запускал
   `scheduleReconnect()` в фоне («зомби» продолжал переподключаться и
   опрашивать Deriv параллельно с рабочим экземпляром).

## Что изменено

- `src/data/providers.config.ts`: `deriv.wsUrl` заменён списком
  `deriv.wsEndpoints` (`ws.binaryws.com`, затем `ws.derivws.com`), добавлен
  `deriv.connectTimeoutMs` (6 с на один хост); `buildDerivWsUrl()` заменён на
  `buildDerivWsUrls()` (порядок приоритета сохраняется, `app_id` добавляется к
  каждому).
- `src/data/sources/deriv.ts`:
  - `openWithFallback()` — перебор эндпоинтов СТРОГО С НАЧАЛА списка при каждом
    вызове; вызывается и из `connect()`, и из `scheduleReconnect()`, поэтому
    каждое переподключение снова начинает с `ws.binaryws.com`, а не «залипает»
    на запасном;
  - таймаут одной попытки + отмена попытки из `disconnect()` (счётчик
    «поколения» `connectGen`);
  - `connect()` при ошибке вызывает `disconnect()` — «зомби» больше не
    остаётся;
  - защита `attachSocket`: `onclose` уже замещённого сокета игнорируется;
  - текст итоговой ошибки называет оба хоста и причину по каждому (виден в
    `errorDetail`).
- Тесты: `deriv.test.ts` (+9: порядок хостов, фолбэк по error/close/timeout,
  «все недоступны», очистка после неудачного connect, рестарт списка при
  reconnect, устаревший сокет, отмена при disconnect) и новый
  `providers.config.test.ts`. Тесты проверены мутациями (удаление очистки,
  guard'а, таймаута, «липкого» хоста — каждая ловится).

## Чего это НЕ гарантирует

Изменение защищает от недоступности одного из двух хостов. Если недоступны
ОБА старых хоста (например, Deriv отключил legacy-API полностью), потребуется
новый публичный эндпоинт `wss://api.derivws.com/trading/v1/options/ws/public`
— он в этой правке не добавлен и не проверялся против живого сервера.

`backtest/data-loader.ts` использует собственную константу `DERIV_WS` и
этой правкой не затронут.
