# CHANGES_APPLIED_ORDER_BLOCK_SPEC.md — доработка Order Block по промту «Алгоритм поиска и отрисовки Order Blocks»

Дата: 2026-08-27.

Промт был написан для абстрактного Python-движка (с жёстко заданными
абсолютными порогами в pip'ах и собственным классом `OrderBlockZone`).
В проекте уже есть свой, более строгий детектор OB
(`src/compute/indicators/smart-money.ts`, используется чартом и
паттернами), нормализованный через ATR, а не через фиксированные pip'ы —
это правильнее (работает на любом инструменте/таймфрейме), поэтому он
не заменён, а **дополнен** тем полезным и корректным, чего в нём не
хватало по сравнению с промтом. Существующая логика принятия решений
(`src/decision/*`) и все паттерны (`src/compute/patterns/*`) —
**не изменены**.

## Что добавлено

### 1. Два недостающих ICT-критерия валидности OB
Промт называет 4 классических критерия валидации OB (liquidity sweep,
displacement+FVG, BOS, fresh zone). В `smart-money.ts` уже были
displacement (ATR-based) и BOS-confluence; добавлены недостающие два —
**как информационные флаги, вычисляемые всегда, но не фильтрующие по
умолчанию** (тот же паттерн, что уже используется в файле для
`hasDisplacement`/`hasStructureConfluence` через `require*` опции):

- `hasFvgConfluence` — импульсная свеча OB действительно создаёт Fair
  Value Gap (та же 3-свечная геометрия, что и везде в проекте, через
  `detectFvgGeometry`).
- `hasLiquiditySweep` — свеча OB перед импульсом пробила недавний
  локальный минимум/максимум (классический "стоп-хант" перед
  накоплением/распределением).

Обе включаются строгим фильтром через новые опции `requireFvgConfluence`
/ `requireLiquiditySweep` (по умолчанию `false`), чтобы не сократить
незаметно список OB для существующих потребителей
(`pattern-context.ts`, чарт, тесты) — включение оставлено осознанным
выбором, а не побочным эффектом.

### 2. Mean Threshold (50% тела OB) — корректная ICT точка входа
Добавлены поля `bodyTop`, `bodyBottom`, `meanThreshold` — граница и
середина именно **тела** свечи OB (open/close), а не всего диапазона
(high/low), как того требует ICT-методология ("mean threshold" — это
50% тела, а не 50% фитиля). Раньше в проекте такой линии для OB не было
вовсе (в отличие от FVG, у которого CE-линия уже рисовалась).

### 3. Корректная отрисовка по состояниям (Fresh / Tested / Invalidated)
`ChartPanel.tsx` и `BoxOverlayPrimitive.ts`:

- **Fresh** — сплошная рамка, заливка по силе зоны, метка «OB», линия
  mean threshold показана.
- **Tested (mitigation)** — пунктирная рамка, метка «mOB×N» (N — число
  касаний), линия mean threshold показана (зона всё ещё рабочая — цена
  вошла, но не закрылась за пределами).
- **Invalidated** — зона окрашена в нейтральный серый (а не в цвет
  направления), чтобы мёртвую зону нельзя было спутать с активной,
  зафиксирована по свече инвалидации (не тянется до текущей свечи),
  метка «iOB», линия mean threshold не рисуется (реагировать больше не
  на что).

`BoxOverlayPrimitive` получил `midLinePrice` — линию по конкретной
цене, а не по геометрической середине бокса (нужно, т.к. mean threshold
— это середина ТЕЛА, а сам бокс рисуется по high/low, и эти середины
не совпадают при наличии теней). Существующее поведение `midLine`
(геометрическая середина, используется для FVG CE) не тронуто.

## Что сознательно НЕ взято из промта

- **Абсолютные pip-пороги** (`min_move_pips=0.0008`, `max_ob_size_pips`)
  — не переносились: они жёстко привязаны к форекс-пипсам одного
  порядка и ломаются на других инструментах/таймфреймах. В проекте уже
  есть эквивалентный, но универсальный ATR-based порог
  (`minDisplacementAtrMultiple`) — он и остаётся источником истины.
- **Переопределение термина "mitigated"** — промт использует
  "Mitigation" в значении «цена вернулась, но НЕ пробила» (= `tested-hold`
  в проекте), тогда как в проекте `mitigated` уже осознанно означает
  «зона пробита» (= `status === 'broken'`) — это тоже распространённое
  в ICT/SMC-индикаторах значение термина, зафиксированное в более
  ранней доработке (см. `CHANGES_APPLIED_FVG_AUDIT_FIX.md`). Менять
  смысл существующего поля не стали — от него зависит остальной код.
- **Breaker Block как отдельная роль-инверсия** и **Nested OB
  (мультитаймфреймовое вложение)** — оставлены на будущее: это не
  правки существующей отрисовки, а новые торговые сущности, которые
  требуют изменений в `src/decision/*` и/или мультитаймфреймовые данные
  — вне рамок задачи «поиск и отрисовка».

## Изменённые файлы

- `src/compute/indicators/smart-money.ts` — новые поля/опции на
  `SmartMoneyOrderBlock` (см. выше), обратная совместимость сохранена
  (все новые опции по умолчанию не меняют текущий список блоков).
- `src/ui/BoxOverlayPrimitive.ts` — добавлен `midLinePrice`.
- `src/ui/ChartPanel.tsx` — состояния OB (fresh/tested/invalidated)
  рисуются по-разному; добавлена линия mean threshold.
- `src/compute/patterns.test.ts` — 3 тестовых фикстуры, создающие
  `SmartMoneyOrderBlock` напрямую, дополнены новыми обязательными
  полями (иначе typecheck красный).

## Проверено

- `tsc --noEmit` — 0 ошибок, относящихся к изменённым файлам (в
  песочнице нет доступа к npm-реестру для полной установки зависимостей
  проекта — `zustand`/`vitest`/`react`/`lightweight-charts` и т.п.
  недоступны для скачивания, поэтому полный `npm run typecheck` /
  `npm run test` не запускались; typecheck прогнан вручную через
  локально установленный `typescript` с теми же `compilerOptions`,
  что и `tsconfig.app.json`, отфильтровав шум от отсутствующих
  `node_modules`). Реальная опечатка была найдена и исправлена именно
  так — 3 тестовые фикстуры не собирались из-за новых обязательных
  полей, добавленных этой правкой.
