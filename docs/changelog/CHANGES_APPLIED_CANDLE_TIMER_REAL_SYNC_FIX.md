# Fix: таймер обратного отсчёта свечи не был синхронизирован с реальным открытием/закрытием свечи

## Симптом

Попросили проверить синхронизацию таймера обратного отсчёта свечи
(`CandleTimer.tsx`, виден в шапке терминала) с реальным открытием и
закрытием свечи.

## Что нашёл

`CandleTimer.tsx` вычислял границу текущей свечи **только** по формуле:

```ts
const currentPeriodOpen = Math.floor(nowMs / tfMs) * tfSec;
```

То есть считал, что границы свечей идеально выровнены по эпохе Unix и
идут непрерывно — и полностью игнорировал `state.candles` из
`useTickStore`. Компонент даже не подписывался на реальные свечи (не
было ни одного обращения к `candles` в файле, тест на компонент
отсутствовал).

Это расходится с реальным источником истины, которым для всей
остальной торговой логики служит **время последней реальной свечи**
(`state.candles[last].time`) — именно от него считают границы:

- `schedulePreCloseTimer()` / `maybeTriggerPreClose()` в
  `tick-store/pre-close.ts` (когда реально показывать пре-close сигнал);
- `deriveCandleLifecycleState()` в `useTickStore.ts` (когда свеча
  реально закрылась / устарела);
- `checkExpiries()` в `useDemoAccountStore.ts` (когда реально
  экспирирует сделка).

Расхождение между "часами" `CandleTimer` и реальными свечами
проявляется как минимум в двух воспроизводимых случаях:

1. **Форекс/индексы и выходные.** `compactTimeline()`
   (`src/data/compact-timeline.ts`) намеренно пропускает выходные дни
   для нерыночных активов. После паузы реальная последняя свеча стоит
   не там, где её "предсказывает" непрерывная wall-clock формула —
   именно в момент открытия рынка, когда пользователю особенно важен
   точный отсчёт.
2. **Лаг / переподключение фида.** Пока `candleLifecycle !== 'live'`
   (фид завис — для этого специально есть отдельный визуальный
   индикатор "Нет данных"), реальная свеча не обновляется, а старый
   таймер продолжал бы бодро отсчитывать несуществующие циклы, создавая
   ложное впечатление, что новая свеча вот-вот откроется/закроется,
   хотя реального движения в данных нет.

## Исправление

`CandleTimer.tsx` теперь берёт время последней реальной свечи из
`useTickStore` и строит отсчёт от него; на formulu
`Math.floor(nowMs / tfMs) * tfSec` теперь опирается только временно, до
прихода самой первой свечи (когда `state.candles` ещё пуст):

```ts
const lastCandleTime = useTickStore((s) => {
  const candles = s.candles;
  return candles.length > 0 ? candles[candles.length - 1].time : null;
});
...
const currentPeriodOpen = lastCandleTime ?? Math.floor(nowMs / tfMs) * tfSec;
```

`progress`/`elapsedInCycle` пересчитаны от той же реальной границы
(вместо `nowMs % tfMs`), с клэмпом `[0, tfMs]` на случай, если фид
отстаёт и реальная свеча ещё не закрылась к моменту, когда "чистый"
таймер уже показал бы 0:00 — в этом случае отсчёт корректно
останавливается на `0:00` и полагается на уже существующий индикатор
`isStale` ("Нет данных"), а не показывает недостоверную цифру.

## Тесты

Добавлен `src/ui/CandleTimer.test.tsx` (компонент раньше не был
покрыт тестами вообще):

- `derives the countdown from the real last candle, not from raw
  epoch-aligned wall clock` — реальная свеча открыта в момент, намеренно
  не кратный длине таймфрейма (как после пропуска выходных); тест
  проверяет, что отображается `4:00` (реальные 4 минуты до закрытия
  РЕАЛЬНОЙ свечи), а не число, посчитанное по "чистой" эпоха-выровненной
  границе. **Проверено, что без фикса этот тест падает** (старая логика
  показывала `0:03` вместо `4:00`).
- `falls back to epoch-aligned estimate only when no real candle has
  loaded yet` — базовая проверка, что компонент не падает до прихода
  первой свечи.

`npm run typecheck` — чисто. `npm run test` — 685/685 (было 683/683 до
добавления двух новых тестов). `npm run build` — без ошибок.
