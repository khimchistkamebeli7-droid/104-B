# CHANGES_APPLIED — методология horizon-audit: независимость, безубыточность, паритет с приложением (2026-09-20)

Основание: разбор отчётов A′.5 (форекс 4 пары, крипто 4 монеты, 2026-03-01 → 2026-09-17) и кода. Затронут **только слой аудита (`backtest/`)** и одна аддитивная диагностика в детекторах; **логика сигналов приложения не менялась** (пороги, множители, направления — как были).

## Что было не так (найдено чтением кода и отчётов)

1. **Единственный `valid` (`harmonic-pattern`) держался на перекрытии наблюдений.** p=0.0000 считался по 10 792 (крипто) / 6 766 (форекс) срабатываниям, а независимых — порядка 1 148 / 754 (колонка «Независимых» в отчёте): один сетап срабатывает на десятках подряд идущих баров, а горизонты по 30 баров перекрываются. В колонке «p (дедуп.)» тех же отчётов — 0.1739 / 0.1467, т.е. **не значимо**. Статус `valid`, Wilson-граница и Holm брались по сырым данным.
2. **Нулевая гипотеза — 50%, а не безубыточность.** Контракт с выплатой 80% (дефолт приложения) безубыточен при 55.56%; при 90% — 52.63%. «Лучше 50%» ≠ «прибыльно».
3. **Аудит мерил детекторы не в той конфигурации, что у пользователя.** `activeFeatures` аудита состоял только из имён паттернов, тогда как в приложении по умолчанию включены все индикаторы (`ALL_INDICATOR_FEATURES`). Поэтому `snapshot.bollinger*`, `emaFast/emaSlow`, `macd` в аудите были `null`: `mean-reversion` первой же строкой возвращал `null` (Bollinger), а `fvg-return`/`fvg-nested`/`fvg-rejection`/`fvg-breaker-block`/`order-block-breaker` (EMA50-выравнивание) и `impulse-breakout` (ширина полос Bollinger) считались без этих входов.
4. **Нет ответа на вопрос «где детектор отсеивает кандидатов»** — «недостаточно данных» / «нет срабатываний» не говорят, какой гейт виноват.
5. **Дрейф рынка не контролировался**: односторонние buy-сигналы на растущем рынке выглядят «точностью».
6. **Нет теста на данных без предсказуемости** — методологическая утечка (перекрытие, look-ahead) не поймалась бы ничем.
7. **Таблица горизонтов не связана с версией алгоритма**: `--check` сверял её с JSON, но не JSON с текущими детекторами.

## Что сделано

### Аудит (`backtest/horizon-audit.ts`, `horizon-verdict.ts`, `audit-version.ts`)
- **Вердикт по независимым наблюдениям (схема 2).** Значимость, Wilson-граница и Holm считаются по дедуплицированному набору; сырые `pValue/significant/passesWilsonGate` остаются в отчёте только для сравнения. Вся логика вердикта — чистые функции в `horizon-verdict.ts`, общие для аудита и генератора таблицы (нет второй копии, которая могла бы разойтись).
- **`--dedupe-scope=pool|symbol`** (по умолчанию `pool`). `pool`: сигналы одного направления на любых инструментах пула ближе горизонта по времени — одно событие (BTC/ETH/SOL/BNB и forex-пары с общей валютой движутся почти синхронно). `symbol` — прежняя независимость только внутри инструмента.
- **`--payout=80`.** Допуск (`valid`) требует, чтобы нижняя граница Уилсона (по независимым) была **выше** `max(безубыточность при payout, дрейф-baseline)` (строго). Безубыточность — из `breakevenWinRateFromProfitPercent` (единый источник экономики). Некорректный `--payout` — ошибка, а не молчаливый дефолт.
- **Дрейф-baseline** (`driftBaselineFromCounts`): ожидаемая точность «случайного» направления с тем же соотношением buy/sell и на тех же барах/горизонтах. Односторонние buy при 62% ростов цены дают baseline 62% — «эджа» нет.
- **Holm по дедуплицированному семейству** (`holmStepDown`, вынесен из прежнего `holmBonferroni`, поведение сырой Holm не менялось).
- **`--indicators=live|none`** (по умолчанию `live` — тот же набор, что включён у пользователя; `none` воспроизводит старое поведение). Совпадение наборов закреплено тестом. `OCCURRENCE_ALGORITHM_VERSION` **4 → 5**: состав `detectAllPatterns` в аудите изменился, старый occurrence-кэш (версия 4) молча отдавал бы результаты без индикаторов. Версия вынесена в лёгкий модуль `audit-version.ts` (реэкспорт из `horizon-audit.ts` сохранён).
- **`--funnel`** — воронка гейтов инструментированных детекторов в отчёте и JSON (`gateFunnel`); occurrence-кэш при этом не читается. Инструментация — `src/compute/patterns/gate-trace.ts`: вызовы `gate('детектор:NN-этап')` **добавлены** после существующих проверок в `hammer`, `inverted-hammer`, `hanging-man`, `shooting-star` (`single.ts`) и `mean-reversion` (`mean-reversion.ts`); ни одно условие/порог не менялось (diff — только добавленные строки; тест сравнивает occurrences с трассировкой и без неё побитово). Вне трассировки `gate()` — одна проверка на `null`. **Остальные детекторы в воронке не участвуют.**
- **Отчёт (`.md`)**: шапка (payout, безубыточность, scope, индикаторы, версия алгоритма), сводка «valid / rejected / значимых по дедуп. / значимых по сырым», колонки «Независ. (все)», «Независ. test», «Acc дедуп.», «Значим (дедуп.)», «Wilson LB дедуп.», «Нужно >», «Вердикт». JSON: `auditSchemaVersion: 2`, `algorithmVersion`, `payoutPercent`, `breakevenRate`, `dedupeScope`, `indicators` и дедуп-поля по каждому паттерну.
- «Независимых» в отчёте = дедуплицированные наблюдения по **всей истории** (train+test); вердикт строится по «Независ. test» — решённым независимым исходам в тестовых фолдах (оно меньше).

### Генератор таблицы (`backtest/generate-pattern-horizon-table.ts`)
- Для отчётов со схемой ≥ 2 статус считается через `classifyDeduped` (пересчёт из примитивов JSON, не из сохранённого `verdict`); поля `entry` — дедуплицированные.
- **Legacy-отчёты (без `auditSchemaVersion`) классифицируются по-старому**, поэтому закоммиченная таблица не изменилась (`--check` зелёный). Для них печатается предупреждение: `valid` получен по сырым p-value.
- `--check` падает, если у отчёта схемы 2 `algorithmVersion` ≠ текущей; `--check --strict` (`npm run backtest:gen-horizon-table:check:strict`) падает и на legacy. В `npm run ci` остаётся нестрогий `--check`, чтобы закоммиченные (восстановленные из docx) отчёты не краснили CI.

### CI-воркфлоу (`.github/workflows/horizon-audit-full.yml`)
- Новые входы `workflow_dispatch`: `payout` (по умолчанию `80`, передаётся как `--payout`) и `funnel` (boolean, по умолчанию `true`, добавляет `--funnel`). Проверка наличия `process.exit(0)` в `horizon-audit.ts` сохранена — вызов на месте.
- При `funnel=true` occurrence-кэш паттернов не читается (иначе детекторы не запускаются и воронка неполная) — прогон пересчитывается полностью. Первый прогон после этих правок и так пересчитывается целиком (`OCCURRENCE_ALGORITHM_VERSION` 5 меняет fingerprint кэша), но на последующих запусках, где воронка не нужна, снимите галочку `funnel`, чтобы использовать кэш. Кэш свечей (`backtest/.candle-cache`) версией алгоритма не затрагивается.
- Вход и выражение `${{ inputs.funnel && '--funnel' || '' }}` проверены только разбором YAML; в GitHub Actions воркфлоу не запускался.

### Новые инструменты
- `npm run backtest:null-audit` — тот же конвейер на синтетическом случайном блуждании (`backtest/synthetic/random-walk.ts`): точность ≈50%, `valid` быть не должно (иначе код возврата 1). Опции `--bars --noise --seeds --payout --dedupe-scope --indicators`.
- `npm run backtest:microstructure-audit` — автокорреляция минутных доходностей ρ₁…ρ₅, доля «ничьих», VR(2) на реальных данных (`backtest/microstructure.ts`). Ответ на вопрос «есть ли на ваших данных отрицательная автокорреляция, объясняющая, почему continuation-паттерны на 1m проигрывают 50%». Пишет `microstructure-audit-*.md` (префикс не `horizon-audit-`, генератор его не читает).

## Что НЕ менялось — и почему
- **Пороги и логика детекторов.** Владелец зафиксировал (`CHANGES_APPLIED_AUDIT_REVIEW_FIXES_20260920.md`, «Намеренно НЕ менялось»): confidence hammer/shooting-star, RSI-гейт, сессионные гейты, сами стратегии. Воронка нужна именно для того, чтобы такое решение принималось по данным, а не наугад. Ослабление гейтов само по себе не создаёт эдж и должно идти через `LOGIC_CHANGE_LOG` + форвард-тест.
- **Направление паттернов не инвертировалось** (v1.6 чек-листа: инверсия по test-выборке того же прогона = дообучение). Инструмента «прогнать инвертированный сигнал» намеренно нет: результат такого прогона нельзя допускать в таблицу горизонтов. Если гипотеза «fade» проверяется — отдельным заранее заданным прогоном на новых данных.
- **`src/decision/pattern-horizon-table.ts` не перегенерирован** — для этого нужен новый прогон аудита (нет сети/свечей); руками автогенерируемый файл править нельзя.
- **`LOGIC_CHANGE_LOG` не менялся**: поведение приложения не изменилось, часы форвард-теста сбрасывать не за что. При перегенерации таблицы после нового прогона (это меняет, какие паттерны подавляются) — добавить запись по протоколу.
- Композитный слой решений (`direction-prediction`, фильтры, калибровка) по-прежнему отчётами horizon-audit не проверяется — это отдельная задача (`npm run backtest`).
- Вариант (б) из `DECISION_INSTRUMENT_CORRELATION.md` (оценка эффективного размера выборки по корреляционной матрице) не реализован: `--dedupe-scope=pool` — консервативная кластеризация по времени, а не оценка корреляции; сырые occurrences по-прежнему не сохраняются в `backtest/output/`.

## Что остаётся сделать вручную (нужны данные/сеть)
1. Перезапустить аудит: `npm run backtest:horizon-audit -- --symbols=… --timeframe=1m --split=walkforward --wf-folds=8 --payout=80 --funnel` (по пулу крипто и форекс отдельно). Прежние числа по `fvg-*`, `order-block-breaker`, `impulse-breakout`, `mean-reversion` получены без EMA50/Bollinger в снапшоте — **после перезапуска они могут измениться**.
2. `npm run backtest:gen-horizon-table`, затем `npm run backtest:gen-horizon-table:check:strict` и `npm run ci`; решения — по колонке «Вердикт». Ожидаемо: `harmonic-pattern` перестанет быть `valid` (p дедуп. 0.17 / 0.15; безубыточность 55.56%). Записать в `LOGIC_CHANGE_LOG`.
3. `npm run backtest:microstructure-audit` на тех же инструментах; `npm run backtest:null-audit` — убедиться, что `valid=0`.
4. Аудит на 5m/15m (`--timeframe=5m`): шум 1m относительно диапазона больше, чем на старших ТФ; но и наблюдений меньше — нужна более длинная история.
5. Аудит композитного сигнала (`npm run backtest` с реальной выплатой).
