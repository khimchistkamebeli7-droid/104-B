# Критичный баг: сигналы не создавались вообще (тупик priorityThreshold ↔ sigmoidFallback) — 2026-09-05

## Диагноз (найден пользователем, подтверждён построчным чтением кода)

`src/decision/signal-builder.ts`, `buildSignal()`:

```js
if (priorityThreshold !== undefined && calibratedProbability !== null && calibratedProbability < priorityThreshold) {
  return null;
}
```

Это не баннер-фильтр — это блокировка создания сигнала целиком. Дефолт
`priorityThreshold` в `settingsStore.ts` — 0.75. `sigmoidFallback()` (единственный
источник `calibratedProbability`, пока обученной модели калибровки нет) в
рамках отдельного, более раннего фикса того же дня был зажат в `[0.35, 0.65]`
(чтобы не выдавать необученную оценку за уверенный прогноз). `0.65 < 0.75` —
всегда истина. Итог: `buildSignal()` возвращал `null` на каждом баре, для
любого сигнала, у любого пользователя с дефолтными настройками — и это не
"сигналы реже", а полный самоподдерживающийся тупик: калибровочная модель
обучается на исходах уже созданных сигналов (`MIN_SAMPLES = 100`,
`calibration-model.ts`), а без единого созданного сигнала исходов взяться
неоткуда. Приложение технически было полностью нерабочим "из коробки" —
график двигался, сигналов не появлялось никогда.

## Фикс

Гейт по `priorityThreshold` теперь применяется только когда
`calibrationSource === 'model'` (реальная, обученная оценка уверенности).
Пока модели нет (`calibrationSource === 'fallback'`) — порог не действует
вообще: fallback-вероятность в принципе не является калиброванной оценкой
уверенности (она специально зажата в узкий диапазон именно чтобы не
выглядеть таковой), сравнивать её со слайдером "порог приоритета" (0.5–0.95,
рассчитанным на реальную ML-уверенность) некорректно категориально. Как
только `calibration.isReady()` — `calibrationSource` становится `'model'`, и
фильтр начинает работать так, как был задуман изначально.

Сопутствующие правки:
- `src/stores/tick-store/shared.ts` (`notifySignal`): инвариантная проверка
  "сигнал ниже порога — аномалия, шлём в Sentry" сужена до
  `calibrationSource !== 'fallback'` — иначе каждый легитимный
  bootstrap-сигнал (ожидаемо ниже порога, пока модели нет) ложно спамил бы
  `captureError`.
- `src/ui/SettingsPanel.tsx`: текст рядом со слайдером порога дополнен
  пояснением про bootstrap-исключение (раньше был технически неточен).
- Побутно найден и исправлен лишний `calibration!` non-null assertion в
  `reviseSignal()` (ловил `eslint`, не влиял на рантайм) и два теста,
  проверявших "модель готова" всего на 15 сэмплах при
  `MIN_SAMPLES = 100` — тесты "проходили", но фактически не тестировали
  ветку `calibrationSource === 'model'` вообще (см.
  `signal-builder.test.ts`). Плюс тест `sigmoidFallback > returns higher
  probability for higher score`, сравнивавший `sigmoidFallback(5)` и
  `sigmoidFallback(10)` — оба клэмпятся в один и тот же потолок 0.65 после
  более раннего фикса того же дня, тест был обречён падать.
