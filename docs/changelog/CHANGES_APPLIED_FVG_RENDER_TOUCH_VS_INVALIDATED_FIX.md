# CHANGES_APPLIED_FVG_RENDER_TOUCH_VS_INVALIDATED_FIX.md

Дата: 2026-08-26.

## Контекст

Аудит присланных документов («Алгоритм поиска и отрисовки FVG» и
сопутствующий промт для bolt.new) показал, что первый файл не содержит
конкретной методологии отрисовки FVG — это общий шаблон роли «команда
экспертов», без правил геометрии/CE/инвалидации. Реальная методология уже
реализована в коде (`fvg-core.ts`, `smart-money.ts`,
`order-block-strength.ts`) и в целом соответствует общепринятой
ICT/SMC-практике. Ниже — что было проверено как верное и единственная
найденная и исправленная в этом проходе нестыковка.

## Проверено и подтверждено рабочим (без изменений)

1. Геометрия гэпа (3 свечи: left/mid/right), границы зоны — соответствуют
   стандартному ICT-определению FVG.
2. Direction-check средней (импульсной) свечи — гэп на «неправильной»
   средней свече (доджи/разворот) отклоняется.
3. Displacement-фильтр — тело импульсной свечи ≥ 1.2 × ATR(14); при
   недоступном ATR зона не отбрасывается, а помечается
   `hasDisplacement: false`.
4. CE (Consequent Encroachment, 50%-мидлайн) — единая централизованная
   формула в `fvg-core.ts`, используется во всех потребителях.
5. Inversion FVG (IFVG) — создаётся как отдельная зона с противоположной
   полярностью, `time = endTime` исходной зоны, со своим собственным
   touched/invalidated-сканом (не наследует историю касаний материнской
   зоны).
6. Инвалидация и переход в IFVG считаются по цене закрытия свечи, а не по
   тени — тень не должна инвалидировать зону.
7. Цветовая палитра (циан/оранжевый для FVG, приглушённые тона + пунктир
   для IFVG, зелёный/красный для OB) — визуально различима, менять не
   требовалось.
8. CE-линия и IFVG-пунктир — уже исправлены ранее
   (`CHANGES_APPLIED_FVG_AUDIT_FIX.md`), `BoxOverlayPrimitive.ts`
   действительно прокидывает `borderDashed`/`midLine`. Регресса не найдено.

## Найденный и исправленный баг

### `src/ui/ChartPanel.tsx` — правый край FVG/IFVG-бокса обрезался по касанию CE, а не по инвалидации

**Было:**

```ts
const cutoff = fvg.broken ? fvg.endTime : fvg.touchedTime;
```

Бокс на графике визуально «заканчивался» уже в момент первого касания CE
тенью (`touchedTime`), даже если зона ещё не была инвалидирована полным
закрытием через дальнюю границу (`broken`/`endTime`).

Но сигнальный движок (`fvg-return.ts`, `fvg-rejection.ts`,
`fvg-nested.ts`, `fvg-breaker-block.ts`, через `pickFreshUnbrokenFvgs` в
`fvg-strategies-shared.ts`) фильтрует кандидатов исключительно по
`!broken` — `touchedTime` там нигде не используется как критерий
живости зоны. `fvg-return.ts` буквально торгует повторное касание уже
тронутой зоны. Аналогичный принцип уже явно задокументирован в
`order-block-strength.ts`: `touched` — частичная митигация тенью, более
слабый сигнал, чем `invalidated`; фильтровать нужно по `!invalidated`, а
не по `!touched`.

Итог нестыковки: график показывал зону как «закрытую», а сигнальный
движок в этот момент и позже всё ещё считал её живой и мог выдать по ней
сигнал (например, FVG Return) — визуализация не соответствовала тому,
что реально происходит в торговой логике, и не соответствовала
общепринятой ICT-практике (зона валидна до инвалидации, а не до
касания).

**Стало:**

Добавлена единая чистая функция `fvgRenderCutoff()` в
`src/compute/indicators/fvg-core.ts`:

```ts
export function fvgRenderCutoff(zone: { broken: boolean; endTime: number | null }): number | null {
  return zone.broken ? zone.endTime : null;
}
```

`ChartPanel.tsx` теперь использует её для обоих циклов отрисовки (`fvgs`
и `inversionFvgs`) вместо инлайновой обрезки по `touchedTime`. Поле
`touchedTime` в `SmartMoneyFVG` не удалено — оно остаётся информационным
(например, для будущего UI-индикатора «зона уже тронута»), но больше не
влияет на правый край бокса.

Данные (`broken`/`invalidated`/`touched` в `SmartMoneyFVG` и
`ImbalanceZone`) не менялись — изменилось только то, как
`ChartPanel.tsx` превращает эти данные в `toTime` для рендера. Логика
скоринга и сигнальных стратегий не затронута.

Комментарий над полем `touchedTime` в `smart-money.ts` также обновлён —
раньше он ошибочно обосновывал обрезку бокса по касанию; теперь явно
говорит, что касание не должно завершать жизнь зоны на графике.

### Тест

Добавлен `src/compute/indicators/fvg-core.test.ts`:
- touched-но-не-invalidated зона → `fvgRenderCutoff` возвращает `null`
  (бокс тянется до правого края таймскейла, не обрывается на касании);
- invalidated (broken) зона → возвращает `endTime`;
- broken без `endTime` (защитный fallback) → `null`.

### Что не тронуто

- `detectFvgGeometry`, ATR-фильтр, CE, Inversion FVG-детекция — не
  менялись, уже соответствуют методологии.
- Критерий инвалидации остался «закрытие через границу», а не «касание
  тенью» — как и требовалось, ослаблять его до касания было бы неверно
  методологически (участило бы ложные IFVG и понизило бы качество зон).
- `e2e/terminal.spec.ts` проверен — привязок к визуальной длине
  FVG-бокса там нет, обновлять нечего.
