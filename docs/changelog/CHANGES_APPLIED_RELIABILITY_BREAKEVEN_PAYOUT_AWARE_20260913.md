# Фикс: калибровка надёжности паттернов мерила "безубыток" неправильной константой — 2026-09-13

## Баг

`src/lib/pattern-reliability-calibration.ts` считал точку безубыточности
паттерна равной `BREAKEVEN_WIN_RATE = 0.5` — условная монета "1 из 2".
Приложение торгует бинарными контрактами с выплатой `profitPercent`
(по умолчанию 80%) при выигрыше и потерей всей ставки при проигрыше.
Настоящая точка безубыточности для такого контракта:

```
p * profitPercent/100 - (1-p) * 1 = 0   =>   p = 100 / (100 + profitPercent)
```

При `profitPercent = 80` это **55.56%**, а не 50%.

Эффект: `suggestedMultiplierFromWinRate(winRate) = winRate / 0.5`. Паттерн с
реальным винрейтом 53% (EV = 0.53×0.8 − 0.47 = **−4.6%** от ставки — убыточен)
получал множитель `0.53/0.5 = 1.06` — самообучение **усиливало** заведомо
убыточный паттерн. Паттерн ровно на настоящем безубытке 55.56% получал 1.11
вместо честного 1.0. Только патттерны ниже 50% реального винрейта вообще
получали понижающий множитель — то есть система систематически считала
надёжными все паттерны в диапазоне 50–55.56%, которые в реальности убыточны
при текущем payout счёта.

Это напрямую объясняет симптом "после всех настроек сигналы остаются такими
же ложными, баланс демо-счёта продолжает падать даже при ~55% винрейте":
механизм самокалибровки не позволял системе распознать и понизить вес
паттернов, которые формально "почти прибыльны", а по факту чуть ниже
реальной точки безубыточности.

## Фикс (логика построения константы, диапазон множителей не менялся)

- Добавлена `breakevenWinRateFromProfitPercent(profitPercent)` —
  `100 / (100 + profitPercent)`, с откатом на `profitPercent = 80` при
  некорректном входе (0, отрицательное, NaN).
- `suggestedMultiplierFromWinRate(winRate, breakevenWinRate)` теперь требует
  `breakevenWinRate` явным аргументом — без дефолта на 0.5, чтобы ни один
  вызов не мог тихо откатиться на неверную константу.
- `computeReliabilitySuggestions(factorStats, currentOverrides, breakevenWinRate)`
  пробрасывает то же значение дальше; дефолт при отсутствии явного значения —
  честный безубыток для payout 80% (55.56%), а не монета 50/50.
- `CalibrationPanel.tsx` теперь читает `profitPercent` из
  `useDemoAccountStore` (тот же источник, что использует `resolveTrade()`
  при закрытии реальных демо-сделок) и передаёт производный от него
  безубыток в `computeReliabilitySuggestions`. Пояснительный текст под
  кнопкой "Калибровать" обновлён — раньше буквально называл формулу
  "winRate / 0.5", теперь показывает фактический безубыток в процентах,
  выведенный из текущей выплаты счёта.
- `RELIABILITY_MULTIPLIER_MIN`/`RELIABILITY_MULTIPLIER_MAX` (диапазон
  клампинга) не тронуты — фикс не сужает и не расширяет веса/пороги, только
  исправляет опорную точку, от которой считается множитель.

## Тесты

`src/lib/pattern-reliability-calibration.test.ts` переписан:
- новые тесты на `breakevenWinRateFromProfitPercent` (80% → 55.56%, 100% →
  50%, более низкий payout → более высокий требуемый винрейт, фолбэк на
  некорректном входе);
- явно показан сам баг и его фикс: винрейт 50% при реальном payout 80%
  теперь получает множитель < 1 (было: ровно 1);
- тест "инструмент с более низким payout получает более строгую планку
  безубытка" — 56% винрейта прибыльно при payout 80%, но убыточно при 60%;
- существующие тесты, не связанные с payout-экономикой (фильтрация по
  сэмплам, exclusion-правила, сортировка, `toMultiplierUpdates`), обновлены
  под новую обязательную сигнатуру — им явно передан `breakevenWinRate=0.5`,
  чтобы не завязывать их на конкретное число безубытка.
