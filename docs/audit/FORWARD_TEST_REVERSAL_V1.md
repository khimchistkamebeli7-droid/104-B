# Предзаданный форвард-тест: «разворот после самой крупной свечи» (reversal-top1pct-v1)

Зарегистрировано: 2026-09-20. Правила — `backtest/forward-test-registry.ts` (заморожены; правка после старта = новый id и новый форвард с нуля).

## Откуда гипотеза (что уже наблюдалось — это НЕ доказательство)
`backtest/continuation-audit.ts`, 1m, разворотная сделка против свечи, вход по open следующего бара, безубыток при выплате 80% = 55,56%.
Корзина силы 99–100% (тело/ATR(14) в верхнем 1%), горизонт 1 бар, доля выигрыша разворота:

| Период | EURUSD | USDJPY | BTCUSDT | ETHUSDT | Пул (n≈) |
|---|---|---|---|---|---|
| 2026-03-01…09-17 (обнаружение) | 54,2% | 59,6% | 54,7% | 56,2% | 56,0% (9 000) |
| 2025-09-01…2026-02-28 (отложенный) | 51,2% | 52,0% | 56,4% | 59,0% | 55,4% (7 300) |

- Знак эффекта (разворот) сохраняется везде; контроль случайного знака в норме.
- **Единственный инструмент, прошедший порог в выборке обнаружения (USDJPY, 59,6%), НЕ подтвердился на отложенном периоде (52,0%).** В отложенном периоде «лучшим» оказался другой (ETH, 59,0%; в выборке обнаружения он не проходил). Смена «победителя» между периодами — типичный признак шума вокруг значения, близкого к безубытку.
- Пул по четырём инструментам за оба периода ≈ 55,7% (грубо, без поправки на кластеры) при безубытке 55,56%.
- Выбор горизонта 1 бар сделан ПОСЛЕ просмотра этих данных (post hoc). Другие горизонты, корзины и инструменты в вердикт не входят.

Вывод до старта форварда: устойчивый разворот есть, но его величина, вероятно, близка к безубытку. Форвард-тест ниже — единственный способ узнать, выше ли она безубытка; исход «fail» ожидаем и допустим.

## Зарегистрированные параметры
- Пул: EURUSD, USDJPY, BTCUSDT, ETHUSDT (все вместе, без выбора «лучшего»), таймфрейм 1m.
- Сигнал: свеча с телом > 0 и силой = |close−open| / ATR(14 предыдущих баров) ≥ порога инструмента. Порог = 99-й перцентиль силы на окне калибровки 2025-09-01…2026-09-17 (считается `--mode=calibrate`, вписывается в registry до старта).
- Сделка: против направления свечи, вход по open следующего бара, экспирация 1 бар (close следующего бара). Ничьи (close = open) не считаются.
- Выплата 80% → безубыток 55,56%.
- Форвард-период: сигнальные свечи с 2026-09-21T00:00:00Z. Ни одна из этих свечей не использовалась ни в обнаружении, ни в калибровке.

## Правило решения (единственное)
- Официальный вердикт выдаётся ОДИН раз, когда решённых событий пула ≥ 1 600 (`minEvents`). Ориентир: ~1 400 событий в месяц по пулу (по объёму 2026-03…09), то есть 4–6 недель.
- **PASS**, если нижняя граница Уилсона доли выигрыша пула, посчитанная по эффективному n (часовые кластеры, общие для всех инструментов; design effect по кластерной дисперсии), выше 55,56%. Иначе **FAIL**.
- До набора выборки допустим только `--mode=progress`: он печатает число событий и НЕ печатает долей выигрыша.
- Запрещено: продлевать выборку после FAIL, менять пороги/горизонт/пул/выплату, выбирать инструмент или подпериод, повторно запускать evaluate. Любое изменение — новая гипотеза с новым id и новым форвард-периодом.
- Мощность (справочно): чтобы нижняя граница превысила 55,56%, при истинной доле 58% нужно ≈ 1 570 независимых событий; при истинной 56% — ≈ 49 000. Значит, тест надёжно обнаружит только эффект заметно выше безубытка; при истинной доле ~55,7% ожидаем FAIL.

## Что происходит дальше
- **PASS** → допуск к следующему этапу: вторая независимая проверка на новом периоде, затем отдельное решение о стратегии в приложении (новый детектор/фильтр, запись в `LOGIC_CHANGE_LOG` с реальной датой деплоя, форвард самого приложения). Сама по себе PASS торговлей не разрешена.
- **FAIL** → гипотеза закрыта. В приложение ничего не переносится.
- Приложение и `LOGIC_CHANGE_LOG` этим тестом не затрагиваются: он работает только офлайн по свечам.

## Порядок запуска (GitHub Actions → «Forward test — разворот после крупной свечи»)
1. `mode=calibrate` — один раз. Вписать выведенную строку `thresholds: {...}` в `backtest/forward-test-registry.ts`, закоммитить ДО 2026-09-21T00:00Z (фиксирует порог; git-время коммита — доказательство регистрации).
2. `mode=progress` — по желанию, раз в неделю: число событий.
3. `mode=evaluate` — один раз, когда progress покажет ≥ 1 600. Результат — `forward-test-result-reversal-top1pct-v1.md` в артефактах.
