## Как заполнять пустые колонки (обновлено относительно версии для варианта А)

1. Для каждой строки — обязательные **три** значения, не одно (см. `direction-horizon-source-variant-B.md`, раздел 3): лучший `expiryBars` по accuracy на **отложенной test-выборке** (не на данных, по которым подбирался горизонт), сама accuracy, и результат теста значимости против случайного направленного бейзлайна того же размера выборки.
2. Строки 17 (Doji) и 22 (Spinning Top) не заполняются вообще, пока не принято отдельное продуктовое решение об их включении как самостоятельных сигналов.
3. Строки с пометкой "ожидать малую/очень малую выборку" (10, 14 частично, 35, 36, 38a, 38b) — при недостаточном числе сигналов за доступный период истории результат помечается «недостаточно данных», а не вписывается число с ложной точностью.
4. Строка 4 (harmonic-pattern) заполняется **дважды** — для фиксированной сетки и для адаптивного горизонта по длительности AB-ноги — обе цифры сохраняются в таблице для сравнения, не выбирается одна произвольно.
5. Строка 14 (liquidity-sweep, reversal-at-key-level) — отдельно от Фазы 4 промта варианта Б, здесь ещё встаёт вопрос из промта варианта А (Wyckoff Spring/Upthrust): «горизонт до подтверждения направления» и «горизонт до завершения движения» — для варианта Б важен именно первый (это и есть `expiryBars` для расчёта выплаты), но замерять стоит оба, чтобы не терять информацию для возможного пересмотра гипотезы.
6. Строки 39-41 (Consolidation Breakout, Inside Bar, Mean Reversion) добавлены позже остальных 38 — при работе с этим файлом учитывать, что они не проходили тот же первый цикл обсуждения, что паттерны 1-38 (например, для них не выведена отдельная гипотеза по `setupType` или подсемейству, как для liquidity-sweep/harmonic-pattern) — при появлении дополнительных данных по ним в ходе Фазы 4 не удивляться, если потребуется такое же уточнение, как для строк 1-14 в этой редакции.
7. **Число в колонке "Backtest" не считается окончательным, пока не пройдены проверки из промта `refactor-variant-B-binary-options.md`, Фаза 6, пп. 4-5** (тест самой методики статзначимости на синтетических данных, тест на минимальный порог числа сигналов) — заполнение колонки точечным значением без этих проверок — ровно та ошибка, от которой защищает раздел 3 `direction-horizon-source-variant-B.md`.

## Результаты первого прогона horizon-audit (2026-09-16)

**Инструменты**: EURUSD 1m, USDJPY 1m, GBPUSD 5m (через Deriv WebSocket).
**Период**: 2026-06-16 → 2026-09-16.
**Ограничение данных**: Deriv отдаёт максимум ~2881 1m свечей независимо от запрошенного диапазона. Это даёт 2881 свечу для 1m или 577 для 5m — критически мало для теста значимости (порог 200 решённых исходов в test-выборке).
**Разбиение**: train 60% / validation 20% / test 20% (хронологическое), windowSize=500.
**Значимость**: точный двусторонний биномиальный тест против baseline=0.5, поправка Holm-Bonferroni, α=0.05.

### Сводка по прогонам

| Инструмент | TF | 1m свечей | Свечей после ресэмплинга | Срабатываний | Train+Val | Test | Значимых |
|---|---|---|---|---|---|---|---|
| EURUSD | 1m | 2881 | 2881 | 433 | 343 | 90 | 0 |
| USDJPY | 1m | 2881 | 2881 | 375 | 305 | 70 | 0 |
| GBPUSD | 5m | 2881 | 577 | 8 | 0 | 8 | 0 |

**Все 24 оценки (11+11+2 паттернов) — статус "недостаточно данных".** Ни один паттерн не набрал 200 решённых исходов в test-выборке, необходимых для теста значимости.

### Паттерны с наибольшей выборкой (но всё ещё недостаточной)

| Паттерн | Инструмент | Лучший expiry | Test accuracy | Test decided | Train+Val accuracy |
|---|---|---|---|---|---|
| inside-bar | EURUSD 1m | 2 | 62.8% | 43 | 44.0% |
| inside-bar | USDJPY 1m | 3 | 57.5% | 40 | 55.0% |
| strong-order-block-reaction | EURUSD 1m | 2 | 40.0% | 10 | 56.3% |
| strong-order-block-reaction | USDJPY 1m | 5 | 50.0% | 12 | 67.7% |
| impulse-breakout | USDJPY 1m | 2 | 77.8% | 9 | 65.2% |

### Вывод

1. **Текущий объём данных через Deriv недостаточен для статистически значимого вывода** ни по одному из 42 паттернов. Это ограничение источника данных, не методологии.
2. **inside-bar — единственный паттерн с относительно большой выборкой** (225 и 163 срабатывания на EURUSD и USDJPY соответственно), но даже он не достигает порога 200 решённых исходов в test-выборке (43 и 40).
3. **Предварительные числа accuracy** (где есть) не должны использоваться в проде без подтверждения на достаточном объёме данных — это прямо то, от чего защищает раздел 3 `direction-horizon-source-variant-B.md`.
4. **Рекомендация**: для завершения Фазы 4 требуется комбинация мер (в порядке приоритета): (а) исправление пагинации data-loader — выполнено (MAX_PER_REQUEST=5000, без раннего выхода на коротком батче); (б) пулинг по 6-8 инструментам — реализовано в CLI (`--symbols=`); (в) walk-forward вместо одиночного holdout — реализовано (`--split=walkforward`); (г) градуированный Wilson-критерий — реализован (поля `wilsonLowerBound` и `passesWilsonGate` в отчёте); (д) внешний провайдер — только если диагностический эксперимент покажет реальный лимит Deriv, а (б)-(г) не закроют потребность. Повторный прогон с новой методологией ещё не выполнен — требуется сетевой доступ к Deriv WebSocket.

| `horizon-audit-<symbols>-<tf>-walkforward-<from>-<to>.json` | Машинно-читаемый отчёт (walk-forward) |

Команды для генерации:
```bash
# Holdout, pooled
npm run backtest:horizon-audit -- --symbols=EURUSD,USDJPY,GBPUSD --timeframe=1m --from=2026-06-16 --to=2026-09-16 --split=holdout

# Walk-forward, pooled
npm run backtest:horizon-audit -- --symbols=EURUSD,USDJPY,GBPUSD --timeframe=1m --from=2026-06-16 --to=2026-09-16 --split=walkforward --wf-folds=5 --purge-bars=30

# Диагностика глубины истории Deriv
npx tsx --tsconfig backtest/tsconfig.json backtest/diag-pagination.ts -- --symbol=EURUSD --from=2025-01-01 --to=2025-04-01
```

**Внимание**: артефакты не могут быть сгенерированы без сетевого доступа к Deriv WebSocket. Текущая среда выполнения не имеет такого доступа — артефакты должны генерироваться в среде с доступом к API.
